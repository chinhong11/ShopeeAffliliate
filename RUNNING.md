# Running the auto-poster

What's built (README Steps 1–8, Step 7 optional) and how to run, deploy and test it. This page is for developers; the click-by-click setup (keys, Facebook token, hosting, settings, what to do when posting pauses) is in [SETUP.md](SETUP.md).

## Layout
```
src/config.js      .env + config.json (TZ from config.timezone)
src/db.js          SQLite at $DATA_DIR/app.db (drafts, posts, slots, kv, conversions)
src/shopee.js      Affiliate Open API: signed GraphQL, offers, product, short links, images   (Step 1)
src/collect.js     categories × strategies → filters → drafts                               (Step 1)
src/mapping.js     Shopee fields → studio state, placeholder guard (shared with the browser)  (Step 1)
src/pick.js        template, headline, captions (shared with the browser)                   (Step 2)
src/render.js      studio in headless Chromium → $DATA_DIR/out/{draftId}.png                 (Step 3)
src/server.js      review app, /studio/, /posters/, /healthz, JSON API                       (Step 4)
src/views/ public/ server-rendered pages + small vanilla JS, manifest, icons                (Step 4)
src/facebook.js    Graph API: photo post, first comment, carousel, debug_token               (Step 5)
src/publish.js     slot → price re-check → post → log; publish-due CLI                       (Step 5)
src/jobs.js        croner scheduler (Asia/Kuala_Lumpur)                                      (Step 6)
src/telegram.js    optional posters + buttons + reports                                      (Step 7)
src/backup.js      daily app.db backup, keep 7                                               (Step 8)
Dockerfile docker-compose.yml                                                                (Step 8)
```

## Local
```
npm install
cp .env.example .env            # fill it in (never commit .env)
# config.json: fill "categories", e.g. [{"name": "Home & Living", "productCatId": null}]
npm run dev                     # http://localhost:4545 — review app + scheduler
npm run collect                 # collect now (add -- --render to render posters too)
npm run publish-due -- --dry-run   # oldest approved draft → Facebook payload, no API calls
npm run publish-due -- --now       # post the oldest approved draft now (real post)
npm run render-test             # Step 3 acceptance test → $DATA_DIR/render-test/contact.png
npm run studio-test             # real browser on sample products (offline): studio save-back, whole photo, 中文 / Melayu
npm test                        # unit + flow tests (fake Graph / Telegram servers, no real API calls)
```
`SHOPEE_MOCK=1` runs the whole app on built-in sample products, offline. Mock drafts show a MOCK chip and can never be posted to the real Facebook API.
`DISABLE_JOBS=1` runs the web app without the scheduler. `RENDER_TIMEOUT_MS` (default 120000) is the deadline for one poster (t8: twice that); a render that runs over, or whose Chromium process dies, fails and Chromium is restarted for the next one.

## Deploy (one container, one instance, volume at /data)
Any always-on Docker host that deploys from this repo and has a persistent volume (Railway, Render with a disk, Fly.io), or a VPS with `docker compose up -d --build`.
1. Create the service from the GitHub repo; it builds the `Dockerfile` (Playwright v1.56.1 base, same as the npm package, plus `fonts-noto-cjk fonts-noto-color-emoji`, `TZ=Asia/Kuala_Lumpur`).
2. Attach a 1 GB volume mounted at `/data`; 1 GB RAM; exactly 1 instance (no autoscaling, no zero-downtime overlap if the host offers to turn it off). A DB lease also keeps a second copy's scheduler idle.
3. Set every `.env` value in the host's environment settings, `DATA_DIR=/data`, and `PUBLIC_URL` = the host's https URL.
   `TRUST_PROXY` (login limit): leave empty — it is 1 on Railway / Render / Fly (their proxy sets X-Forwarded-For) and off on a bare port (docker-compose on a VPS, where clients could fake that header). Set it if you put your own reverse proxy in front.
4. Health check path: `/healthz`.
5. `config.json` is read from the repo: commit your categories there (it has no secrets).

Backups: `$DATA_DIR/backup/app-YYYY-MM-DD.db`, daily at 03:30, newest 7 kept.
Disk: posters / photos of finished drafts are removed at 00:05 (big PNGs after 2 days, thumbnails and photos after 30), so the volume stays around 50 MB.
Daily jobs (collect, token check, plan + expiry + cleanup, backup) run at their time, or as soon as the service is back if it was down or restarting then; each runs once a day.
Memory: a render peaks at ~400–450 MB of Chromium (t1 / t2) and ~600–700 MB (t8, four photos) plus ~150–200 MB for Node; tested in a container limited to 1 GB.

## First run
1. Open `PUBLIC_URL`, log in with `ADMIN_PASSWORD`, tap ↻ 抓取.
2. Approve one draft.
3. In the host's shell: `npm run publish-due -- --dry-run` and check the payload.
4. One real post: `npm run publish-due -- --now` (or wait for the next slot).
5. Check the Page post and the first comment with the link. Pinning the comment isn't available in the API; pin by hand if wanted.

## Where the build differs from the README (and why)
- **Shopee `sortType`**: 2 = sales, 5 = commission (no discount sort), so 大折扣 ranks the pooled 爆卖 + 高佣 candidates by `priceDiscountRate`, as the README allows. The official docs need an affiliate login; the values come from public descriptions of the Open API. Check them against your docs page once you have keys.
- **`productCatId: null`** falls back to `keyword: name`. Category IDs aren't guessed or written back automatically; put real ones into config.json when you have them.
- **Graph API version**: v26.0 (the current version as of Oct 2026); override with `FB_GRAPH_VERSION`.
- **Studio**: `crossorigin="anonymous"` on the Google Fonts `<link>`. Without it, html-to-image can't read the cross-origin `@font-face` rules, and every export (including the studio's own ⬇ 下载海报) silently fell back to system fonts (no Montserrat, Nunito or Caveat).
- **Studio fit (real data is longer than the demo values)**: `fitText()` in `post-studio-v3.js`, run after every text / price / template / size change and once the fonts are loaded (`PostStudio.fit()` for the renderer after it trims the fonts). (1) Headline: a typed line that would wrap is shrunk, down to 75 %, until it fits on its line (on 杂志封面 three of the five README headlines left one character alone on a third line, e.g. 「还不知道这个」). A line still too long at 75 % keeps the chosen size. (2) 价格暴击 big price: shrunk to end left of the 「评论区拿链接」 button; from RM 10 up it ran under it (RM 19.90 read as "RM 19.9"). The studio's own export does the same, so posters stay identical to it (`npm run render-test`).
- **Renderer**: html-to-image is served from `node_modules` (same 1.11.11) and Google Fonts are cached on disk, so a render doesn't depend on unpkg. Before exporting, the renderer keeps only the font slices the poster can use (its families × the characters in its text): html-to-image otherwise inlines all ~550 Google Fonts slices into every export, which peaked at 0.9–1.4 GB and got Chromium OOM-killed in a 1 GB container. Posters stay pixel-identical to the studio's own export (`npm run render-test`, now also t3, t4 and all four t8 pages). The studio's own ⬇ 下载海报 in your browser still embeds all fonts (slower, fine on a desktop).
- **在 Studio 精修 saves back** (the README only opens the studio with the draft loaded, so nothing changed there reached the post): opened from 编辑, the studio page (`…v3.html?draft=<id>`) gets a bar with 保存到草稿 / 回到 App (`public/studio-bridge.js`, added by the server; the studio files are unchanged). 保存到草稿 sends what changed in the studio (colours, font, text size and alignment, scrim, background, button text, which elements show, headline, review and chat lines, photo zoom and position, carousel captions) to `POST /api/drafts/:id/studio`. It's kept in the draft as `form.look` (checked: hex colours, the studio's five fonts, size 70–140, scrim 0–80) and drawn over the app's poster state, so the posted poster is the studio's own export (0 % of pixels differ, `npm run studio-test`). Product data and settings stay the app's: price, discount, rating, sold, voucher, countdown, the photos and how many show, brand badge, language, captions. The bar names which of those you changed that weren't taken back, and says so when the studio switched to a template the app keeps locked until it has that template's real data. The discount seal and the rating can be hidden there, not turned on where the product doesn't have them. After a studio save the edit page reloads by itself and shows ✨ 这张海报用了 Studio 精修的样式 with 清除; an edit page opened before that save can't write its older look over it.
- **Small price moves (≤ 3 %)** before posting update the poster, headline and captions instead of posting a stale price; > 3 % or gone returns the draft as the README says (also with the new numbers in its headline).
- **Every post carries the affiliate link**: in comment mode in comment ②, in direct mode in caption ① — even if `linkMode` changed after the captions were written. Auto-written captions are regenerated with the current config at post time.
- **5xx is retried once after 60 s, as specified; a POST that got no answer at all (network cut) is not re-sent**, because Facebook may already have published it. It is logged as 失败 with "先到专页看看" before 重试.
- **t3 限时抢购**: the end time is stored with its date when you enter it. A sale that has ended by post time is not posted (no invented countdown): the draft goes back to 待审核 on the automatic template.
- **Token check**: if Facebook can't be reached for the check (network, 5xx, temporary codes) publishing is not paused; the check is retried a minute later. A token pause lifts itself when a later check passes; rate-limit / spam pauses still wait for 重试.
- **Safety**: a draft is claimed for posting with a check-and-set on its status, so a 撤回 / 跳过 during the pre-post checks, or a second publisher (`npm run publish-due -- --now` next to the scheduler), never posts it (or posts it twice). An error before posting (Shopee lookup, render) is logged as 失败 (with Telegram), so it no longer holds up the queue: the next approved draft takes the next slot. `--now` and 重试 respect `postsPerDay`.
- **Review app usability pass** (after a walkthrough on a 360 px phone and an axe accessibility check): the edit page saves by itself (a moment after each change, and when the page is left any way: back gesture, top menu, closing the tab); 跳过 can be undone for 8 s and then from 已跳过 (恢复, while the draft could still be approved); a card's last day before it expires says so; Telegram reminds you an hour before a posting time nothing approved will fill; messages stay long enough to read and close on tap; the pause banner says what happened in plain words, keeps Facebook's own words apart and links the guide ([SETUP.md](SETUP.md)); secondary text is at least 12 px with at least 4.5:1 contrast; tap targets at least 44 px; form labels are tied to their fields. The poster cache key leaves out the caption builder's fields (only 好友爆料 draws the link), so 批准 after a template change no longer renders the same poster again. The edit page shows a 1080 px JPEG instead of the ~1 MB PNG (the PNG is still what gets posted).
- **数据 tab**: shows real post counts. Orders and commission stay "—" until the conversion report (Step 9, not built) fills the `conversions` table. No invented numbers.
- **Studio caption for 我用过**: ported from `buildMain()` in `post-studio-v3.js` (same text as `PostStudio.caption().post`) so it can update live in the edit form.
- **Panel layout for 爆款分享 / 价格暴击 / 杂志封面** (the headline drawn over the photo hid the product): the photo keeps the top of the poster (only the badge and the discount seal on it); headline, price and button sit in a solid panel below (white / cream / dark). Override block at the end of `studio/studio-canvas-v3.css`, so the studio and the renderer stay identical (`npm run render-test`). These three always show the price, also without a discount (`PANEL` in `src/mapping.js`).
- **✨ AI 设计 replaces the template picker and 在 Studio 精修**: Gemini (text model, free tier) picks each draft's template (t1 / t2 / t6) and look (panel and accent colours, headline colours, font, alignment, marker) from its main photo and data; new drafts get one automatically, `/d/:id/designs` shows 4 options drawn with the real photo and price, `用这款` saves one as `form.look`. Colours are checked for contrast before use (`cleanDesign` in `src/gemini.js`). The studio page is still the poster renderer; its editing entry and the template / 买家真实评价 sections are hidden, not deleted.
- **One poster per photo**: a draft with 2–4 photos (not 轮播套图) gets the same design drawn once per photo (`{id}-1..4.png`, `renderDraft`), and they go out together as one multi-photo post (`attached_media`). The first is the cover and the card thumbnail.
- **发布时间 per draft**: the edit page's 发布时间 is 自动排队 (next free slot, as before) or 指定时间 (`form.postAt`). A draft with its own time doesn't take a slot; `publishDue` posts it once its time has come (next minute's check; was every 5 minutes), outside `postsPerDay`; more than 2 h late (app was off) it joins the normal queue instead of posting by surprise. The edit page also shows every page of a multi-photo draft (`{id}-p1..4.jpg`).
- **Gemini usage on 数据**: an API key can't read its own quota, so the app counts its requests (per day, last minute, tokens, by kind) in `kv` and keeps the last limit Google reported (429 `quotaId` per minute / per day, `retryDelay`). Automatic designs wait and retry once after a per-minute limit.
- **Posters at 2× (2160 px)**: `snapshot()` exports with `pixelRatio: 2` (Facebook keeps up to 2048 px), `npm run render-test` expects 2160×2160. A poster PNG over 3.8 MB is posted as a 92 % JPEG of the same size; `graph()` labels uploads by their bytes. Uploaded photos are kept up to 2048 px (was 1080); the import ticks the first 4 gallery photos.
- **Gemini model chosen on 数据**: the text models the key can call (`/v1beta/models`, cached a day, image / speech / live / tool models filtered out); `用这个` overrides `GEMINI_MODEL` (kv `gemini:choice`). RPM / TPM / RPD per model are typed in from AI Studio (Google's rate-limit page has no free-tier table) or learned from a 429's `quotaValue`; today's requests are counted per model. Gemini 3.8 Flash comes filled in as 5 / 250K / 20 (AI Studio, 2026-10-17).
- **Small photos**: a photo the 2160 px export would enlarge more than 2.5× is framed at most 1.25 CSS px per photo px on a blurred copy of itself (`applyPhotoBox`, `.small`), not stretched; photo tiles flag a short side under 800 px with 「会糊」 (`flagSmall` in `public/app.js`). `renderNow` keeps the exact PNG as `png` (render-test) and the possibly-JPEG upload as `post`. Poster colour variables must not share a name with `studio-ui-v3.css` :root (`--panel` did: plain posters came out dark) — `test/css.test.js`. render-test's t3-1 can differ by one countdown second (the studio's live countdown ticks during the 2× export).
- **Poster and caption language per draft (中文 / Bahasa Melayu)**: `form.lang`, set when a draft is made from `config.json` `language` and switched on the edit page (海报和文案的语言). It decides the headline suggestions and the headline a switch picks (same position in the list), caption ① and comment ② (auto-written ones; hand-edited ones stay and the page says so), the words the app puts on the poster (`WORDS` in `src/mapping.js`: button, sold, buyer, flash sale, group chat, carousel captions; `WORDS_MS` in `post-studio-v3.js` for the studio's own labels), ✨ AI 写文案 (Gemini is asked for Malay) and `hashtags` (`{"zh": …, "ms": …}` or one string). The review app stays Chinese; cards of a Malay draft show a Melayu chip. A draft from before this has no `lang` and follows `config.json`. Product names stay as Shopee lists them.
- **Whole photo above the panel**: 爆款分享 / 价格暴击 / 杂志封面 give the photo 1080×610–650; filling it with a square Shopee photo cut 40 % of the product (its top and bottom). A photo the box would cut by more than 10 % is shown whole on a blurred copy of itself (`applyPhotoBox`, `.framed`, the same treatment small photos had); one moved or zoomed by hand is left as set.
- **Headline clear of the price tag**: on 爆款分享 / 杂志封面 the price tag grows with the price (RM 1299.90 covered the end of the headline): the headline box now ends left of it; on 价格暴击, which runs the two typed lines together, a line that would wrap is shrunk like the others (`fitLine1`).
- **Renderer crash while the page loads**: a renderer that dies during the studio page's load (`net::ERR_ABORTED`, frame detached) now counts as a crash and restarts Chromium, like one that dies later (`openStudio`; `test/render.test.js` hit this under load).
- **主页图 (Facebook cover and profile picture)**: a fourth tab designs the Page's cover (1640×720; Facebook shows about 820×312 on a computer and 640×360 on a phone, so the words stay in the middle 640×312) and profile picture (720×720, shown as a circle) from the brand in `config.json`, a language, a few styles and a colour (`src/brand.js`, the same HTML for the live preview and for `renderHtml` in `render.js`). 生成 draws the PNG to download; the choices are kept in `kv` (`brand:design`). The app does not change the Page itself: the Graph API reference documents reading a Page's cover and picture, and I found no current way to set them (a 2025 report says setting the cover fails on v22–v24), so uploading stays the person's step (SETUP.md).
- **贴士 / 梗图 (tips and memes)**: two tabs for posts that aren't products: a daily-life tip card or a two-line meme (text + emoji, or a photo uploaded by the person with the words on top; the file is `img/ct-….jpg`, removed with its draft), 1080×1080 (`src/content.js`, the same HTML for the live preview and `renderHtml`). ✨ asks Gemini for 4 ideas (today's date, Malaysian everyday topics, no 3R or politics, no made-up numbers); the person edits, taps 生成海报 to see the real PNG, then 发布 posts it at once with `postPhoto`. Rows live in the `content` table; a claim (`status='posting'`) stops a double post. 定时发布 sets `scheduled_at` (status `scheduled`); `jobs.js` `postContentDue` posts it in the minute tick, not while posting is paused, and tells Telegram. These posts don't use the daily slots or count toward `postsPerDay` (`posts.strategy = 'content'` is left out of `postedToday`); each posted one gets a `posts` row (`draft_id` `c<id>`), so it shows on 已发布 with its picture (`out/c<id>.png`) and in 数据. `cleanupFiles` keeps a content photo while its post is kept and removes unused `ct-` uploads after a day.
